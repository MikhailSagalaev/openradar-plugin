# Submission plan: how to list this plugin

The same artifact fits several catalogs. Do them in this order.

## 1. xAI plugin marketplace (github.com/xai-org/plugin-marketplace)

Their rules: third-party plugins are referenced as a **remote source pinned to a
full 40-character commit sha**; the component index is generated by their scripts,
never hand-edited; submission = a pull request, code-owner review required.

> **Re-pin after every change.** The sha below must be the commit that contains
> the current files. The commit that synced this plugin with the openradar hub
> 0.25.4 (new `search_leads` contract, connection docs, skill copies for other
> CLIs, manifest moved to `.grok-plugin/plugin.json`) replaces any sha noted
> before it: push it to the public repository, then take the sha again.

1. Push this repository and take the commit sha of what is public:
   `git ls-remote https://github.com/MikhailSagalaev/openradar-plugin.git HEAD`
   (or `git rev-parse HEAD` after the push).
2. Fork `xai-org/plugin-marketplace`, create a branch.
3. Add to `.grok-plugin/marketplace.json` (the `plugins` array). The manifest is
   read from `.grok-plugin/plugin.json` in this repository:

```json
{
  "name": "openradar",
  "description": "Search live freelance orders and remote jobs on openradar, estimate market pay from real leads, contribute observed leads back to the hub.",
  "category": "productivity",
  "source": {
    "source": "url",
    "url": "https://github.com/MikhailSagalaev/openradar-plugin.git",
    "sha": "<full 40-char lowercase sha of this repo>"
  },
  "homepage": "https://openradar.fun",
  "keywords": ["openradar"],
  "domains": ["openradar.fun"]
}
```

   Keep `keywords` and `domains` brand-scoped — they trigger Grok Build's plugin
   suggestion, and generic words are pushed back in review.

4. Run their tooling: `python3 scripts/generate-plugin-index.py`, then
   `python3 scripts/validate-catalog.py` and
   `python3 scripts/generate-plugin-index.py --check` (what their CI runs) —
   commit the regenerated `.grok-plugin/plugin-index.json`.
5. Open the PR. Suggested body:

> Adds the openradar plugin (third-party, remote source pinned to `<sha>`).
> What it does: searches the live openradar feed of freelance orders and remote
> jobs over its public MCP endpoint and HTTP API, estimates market pay from real
> priced leads, and submits radar/2 observations for leads the user legitimately
> saw. Skills read only public endpoints; no keys are required for guest access,
> a participant key stays in an environment variable. Repository:
> https://github.com/MikhailSagalaev/openradar-plugin · Site: https://openradar.fun
> · License AGPL-3.0.

Expectations: the queue is long (~1k open PRs) and xAI explicitly disclaims
third-party plugins — submit and move on; do not block on the review.

Updating a listed plugin: bump `sha` in the existing entry to the new public
commit and regenerate the index — never open a second entry.

## 3. Anthropic-style skill catalogs

The `skills/*/SKILL.md` files follow the common agent-skills format (YAML
frontmatter `name` + `description`, body of instructions) — they can be copied into
any host that loads skills from a directory.

## 4. Own catalog (dogfooding)

Publish this file set under `https://openradar.fun/agents` as the official listing:
the same `marketplace.json` shape, so any agent host can add openradar's catalog as
a source. Optionally advertise it as a radar/2 event kind later.
